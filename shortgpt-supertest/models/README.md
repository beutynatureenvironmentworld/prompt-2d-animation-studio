# ShortGPT SuperTest — Genuine offline open-weight AI engines

These models are **actual CPU neural inference** and not the original six-pose clip or placeholders.

## Audited Apache-2.0 models

| Role | Public HF model | Model download | Tested platform |
|---|---|---:|---|
| Original story/JSON reasoning | [Qwen3-4B-Instruct-2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507), GGUF Q4_K_M from [bartowski](https://huggingface.co/bartowski/Qwen_Qwen3-4B-Instruct-2507-GGUF) | ~2.5 GB | GitHub Actions Ubuntu, CPU |
| New diffusion backgrounds | [Segmind SSD-1B](https://huggingface.co/segmind/SSD-1B), Diffusers FP16 weights | ~4.5 GB selected model components | GitHub Actions Ubuntu, CPU |

Both model licenses are Apache-2.0; each backend uses open-source inference libraries.
**'Open weights' does not make all model outputs or every provider unrestricted.** Consult each model card and acceptable-use guidance.

## Isolation

The project's single-prompt adapter understands:

- `--planner gguf`: real local Qwen3 through llama-cpp-python; produces validated JSON scene plans.
- `--images cpu`: real local Segmind SSD-1B via PyTorch/Diffusers; new cartoon background PNG. Scene pixels are generated by a neural model and cached per location.
- `--tts espeak`: offline English voice. `--tts edge`: network option.
- `--planner offline --images procedural`: reliable free baseline.

You can generate a short in one CLI invocation **after** installing both local models/libraries:

```bash
python shortgpt_supertest.py \
  --prompt "A funny boy runs to a locked toilet door, panics then recovers" \
  --planner gguf --images cpu --tts espeak --output output/real_local_ai_short.mp4
```

The adapter deliberately executes LLM output as **validated JSON**, never as arbitrary generated Python/JS.

### CPU install (GitHub Actions/strong RAM machine)

Run the separate `ShortGPT SuperTest REAL Open-Weights CPU AI` GitHub workflow.
It installs CPU-only PyTorch for SSD-1B in one 16GB runner, and llama.cpp with Qwen3 in another. Both produce **actual** AI outputs as downloadable GitHub artifacts.

On a custom Linux CPU machine with **12–16 GB or more usable RAM** and several GB free disk:

```bash
python -m pip install --no-cache-dir 'llama-cpp-python>=0.3.16,<0.4' 'huggingface_hub>=0.34,<1' 'Pillow>=10.3,<12'
python -m pip install --no-cache-dir 'torch==2.5.1+cpu' --index-url https://download.pytorch.org/whl/cpu
python -m pip install --no-cache-dir 'diffusers==0.35.2' 'transformers==4.57.1' 'accelerate==1.12.0' 'safetensors>=0.4' 'sentencepiece'
python models/offline_inference.py story --prompt "A boy rushes to the toilet and the door is locked" --output output/story-ai.json
python models/offline_inference.py image --prompt "Clean original 2D cel-shaded cartoon bathroom hallway, no person, no text" --output output/background-ai.png
```

SSD-1B's upstream HF repository contains **~26.8 GB** of redundant alternate checkpoints, full precision and variant files; this project downloads only **~4.5 GB required FP16 component files**, then loads them for CPU processing. During CPU inference, RAM use can exceed downloaded weights size substantially.

### Oracle 1GB RAM note

Do **not** run this CPU Diffusers image model on the existing 952 MiB Oracle AI host. Size of filesystem/storage is **not** a substitute for memory. The 469 MB existing local GGUF + llama.cpp can be used for lower-quality constrained planning. Use GitHub hosted runners or a separately provisioned 16GB+ server for Qwen3 4B/SSD-1B.

### Environment variable options

- `HF_HOME` caching path (public model downloads need no HF token)
- `GGUF_MODEL_ID`, `GGUF_MODEL_FILE` alternate GGUF model
- `CPU_IMAGE_MODEL` defaults to `segmind/SSD-1B`
- `CPU_IMAGE_STEPS` default 9 for quality/speed tradeoff (4-5 for smoke tests; 16+ for best results)
- `HF_TOKEN` optional for models requiring authentication; **never paste into the source or GitHub logs**
- Runtime package versions and model loading may need tuning after testing on future environments; no guarantee of fast 1080p CPU diffusion.

### What this does not solve by itself

These are **AI static background images + original vector human foreground motion**, not a generative video diffusion model. For highly natural animation you'd need pose/character consistency tools or an appropriate GPU model. Both weights are downloaded during GitHub jobs and are not committed to GitHub.
